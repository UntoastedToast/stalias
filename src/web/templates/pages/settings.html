Connect to Stalwart

stalias manages aliases through Stalwart's JMAP API (Stalwart 0.16 or newer). It needs an API key that may do exactly what stalias does, and nothing else.

Step by step: create the API key in Stalwart {% include "icons/chevron-down.svg" %}

  1. Sign in to the Stalwart admin UI

    Usually https://your-mail-host/admin. Use an administrator account.

  2. Create a new API key

    Open the Account section of the menu, then

    {{ m::path("Credentials", "API Keys", "") }}

  3. Describe it

    Set Description to the text below. Leave Expiration Date empty, otherwise the key stops working at that date, and leave Allowed IPs empty.

    {{ m::copyrow("apikey-description", "Description", "stalias") }}

  4. Limit what the key may do

    Under Permissions choose Replace all permissions, then add exactly these six. Paste the short name on the right into the search field of the list to find each one.

    {{ m::permrow("perm-1", "Sign in to the server", "authenticate") }} {{ m::permrow("perm-2", "Accounts Management: Get accounts", "sysAccountGet") }} {{ m::permrow("perm-3", "Accounts Management: Query accounts", "sysAccountQuery") }} {{ m::permrow("perm-4", "Accounts Management: Update accounts", "sysAccountUpdate") }} {{ m::permrow("perm-5", "Domains Management: Get domains", "sysDomainGet") }} {{ m::permrow("perm-6", "Domains Management: Query domains", "sysDomainQuery") }}

  5. Save it and copy the secret

    Stalwart shows the Secret only once. Copy it now and paste it into the form below.

{{ m::note("Keep the key private", "It can also reset the password of any mailbox. stalias stores it in its data volume.") }}

Your key

"Test and save" checks the address and the permissions before anything is stored.

Start with http:// or https://. The address only has to work for stalias, it does not have to be public. In the same Docker network use the container name, for example http://stalwart:8080. Otherwise use the address of the admin UI without /admin.
